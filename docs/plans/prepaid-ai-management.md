# 余额账户、Telegram 提醒与 Agent 操作方案

状态：2026-09-15，功能已实现并完成本地测试；尚未部署，见 ../deployment-prepaid.md。

## 已确认的需求

- 保留现有订阅，增加话费、电费、水费等带余额的账户。
- 录入当前余额、每期固定或估算费用、扣费周期和下一次扣费日期。
- 用户已确认：变动费用按估算自动扣减账本余额，之后可以按实际账单或真实余额校正。
- 提醒余额不足和订阅即将续费，使用用户新建的独立 Telegram 通知 Bot，不复用 Hermes 的 Bot 或配置。
- Hermes 及其他 Agent 可以通过接口和 Skill 查询、记录及管理；具体字段不清楚时先补问。
- Hermes 以后可通过 Skill 查询账本并自行推送；其推送链路与账本定时通知分别运行。
- 自动扣减只发生在账本中，不调用运营商、水电平台或支付接口。

## 建议的首版

### 1. 两种记录共用现有周期能力

| 类型 | 主要信息 | 到期行为 |
| --- | --- | --- |
| 订阅 | 每期费用、周期、续费日期 | 延续现有续费记录与确认，增加到期提醒 |
| 余额账户 | 当前账面余额、余额核对日期、每期固定/估算费用、周期、下次扣减日 | 按计划生成一次扣减流水，推进下次日期 |

余额账户展示“账面余额”“费用是否估算”“上次核对时间”。真实平台余额只有在用户提供后才能确认。

月数、年数和月底锚点复用现有规则。首次输入的余额已经包含核对时刻之前的消费，不应再补扣历史周期。新账户的首个自动扣减日应在余额核对日之后。

### 2. 用流水解释余额

- 支持初始余额、充值、周期扣减、实际账单调整、余额校正。
- 余额变动包含金额、时间、来源（用户/Agent/定时任务）和关联记录。
- “充值 100 元”表示增加 100 元；“现在还剩 100 元”表示核对到 100 元，两者必须使用不同操作。
- 已按估算扣减的账期，填入实际账单时只调整差额，不能再扣整笔。
- 余额不足时保留预计欠额并提示，不能将数值悄悄截成零；是否真的欠费仍以平台为准。
- 充值与消费分开统计，避免将充值及后续消耗重复计为支出。

### 3. 确定规则的后台任务

- 由账本执行周期扣减和提醒判断，网页与 Agent 共用同一记账模块。
- 建议使用同一应用镜像的独立 worker，与网页服务共用 SQLite 数据卷；不引入消息队列。
- 扣减使用事务，并以“账户 + 账期”唯一约束防止任务重试或进程重启重复扣款。
- 短暂停机后补齐余额核对日之后漏掉的周期，保留原周期锚点。
- 提醒记录持久化发送结果，失败可重试；同一账期同一提醒阶段正常只发送一次。
- 扣减与提醒由账本独立调度，不依赖模型推理、Hermes 服务或 Hermes cron；即使 Hermes 停止运行，账本仍照常扣减和推送。

### 4. 提醒规则与 Telegram

建议默认规则，可在设置中修改：

- 普通订阅：到期前 3 天及到期当天提醒。
- 余额账户：立即提示已经不足下一期费用；提前 3 天预测下次扣减后是否低于阈值；扣减后若不足下一期费用也应提醒。
- 只在首次命中或状态变化时推送，避免每次检查重复提醒；充值或校正后重新计算。
- 每条提醒包含名称、日期、账面余额、固定/估算费用、预计缺额和详情入口。估算数字明确标注。
- 用户通过 BotFather 新建专用通知 Bot，先在私聊中向该 Bot 发送 `/start`，再配置通知所用的 Bot Token 和目标 chat ID。
- 账本独立管理通知配置、发送和重试，不读取或挂载 Hermes 的配置目录，不复用 Hermes Bot Token。
- 首版通知 Bot 只负责发送消息，不处理自然语言记账；用户与 Hermes 的对话保留在 Hermes 原有入口。
- 发送目标绑定服务器配置，不接受 Agent 在请求中任意指定收件人。
- Bot Token 仅保存在服务端秘密配置中，配置检查不回显完整值，也不写入代码、Skill 正文或备份。

### 5. Agent 接口与 Skill

- 提供版本化 HTTP 接口和 OpenAPI 文档，覆盖查询、新建、修改计划、充值、补录实际账单、校正余额、记录续费和查询待办。
- Agent 使用独立可撤销的访问令牌；网页继续使用原 Cookie/CSRF 登录，不向 Agent 提供网页登录密码。
- 写操作携带请求标识，重复调用返回同一次操作结果；同名账户先定位或补问，不按第一条结果猜测。
- 接口负责日期、金额、余额及去重规则，Skill 负责意图映射、调用步骤和回读验证。
- 输出适用于 Hermes 的 `SKILL.md`、轻量客户端脚本、示例及凭据配置说明；令牌不写入 Skill 正文或 Git。
- Skill 可以按需获取待续费和余额不足的结构化结果，Hermes 再通过自己的通知能力单独推送；该过程不参与账本通知的调度或发送状态。
- 账本自动提醒与 Hermes 自行推送各自记录来源；Hermes 查询不会将账本提醒标记为已发送。两边如果同时设置同一提醒，可能分别发出，属于两个独立任务。
- Agent 普通权限不包含数据库恢复、清库或设置 Telegram 收件人。需要删除记录等操作时，按用户明确意图处理。

示例：

> 记一下手机套餐，每月 1 号扣 59 元，现在余额 120 元。
>
> 话费刚充值了 100 元。
>
> 水费每月大概 35 元，余额 90 元，每月 15 号扣。
>
> 这次水费实际是 41 元，修正一下。
>
> 电费平台显示实际还剩 83 元，帮我校正。
>
> 看看未来两周有哪些订阅要续费、哪些余额要充值。

## 实施顺序

1. 余额账户与流水、日期和金额规则、网页录入与校正。
2. 定时扣减、提醒持久化、独立 Telegram 通知 Bot 配置、发送和失败重试。
3. Agent 访问令牌、接口文档和 Hermes Skill；使用隔离数据验证自然语言到写入的完整链路。
4. 备份格式兼容与迁移说明、生产构建、部署前备份、按明确计划部署和验证。

关键验收：月底/闰年、同一期重试不重复扣减、停机补扣、充值与校正区别、实际账单只补差额、预测不足、消息去重、旧备份兼容、Agent 重试不重复记账、越权拒绝、Hermes 停机时账本仍正常提醒。
